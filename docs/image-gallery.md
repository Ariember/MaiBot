# 表情包与额外图库

「学习 → 表情包」提供表情包库和额外图库两个入口。表情包库继续使用原有注册、丢弃和发送流程；额外图库保存普通图片和表情包，支持标签检索、原图发送，以及加入表情包库。

## 使用

- 在「额外图库」上传 JPG、PNG、GIF、WebP 或 BMP 图片，或将文件放入页面显示的图库目录后点击「扫描目录」。支持子目录，文件名和目录名会作为初始标签。
- 点击图片预览原图；「标签」编辑手动标签，自动标签会单独保留。「据为己用」将图片复制到原有表情包目录并立即加入可发送候选，遵守注册上限、丢弃状态和内容审核设置。
- 网页聊天室中打开输入区的表情选择器，切换「额外图库」，浏览、搜索并发送图片。带「表情包」标签的图片作为表情消息发送，其他图片作为普通图片发送。
- 在对话中请求「从图库找一张开心的图片」，机器人可调用内置 `search_images` 工具按描述选图并发送。该工具同时适用于两种表情包发送模式。

自动标签复用「功能分配 → 图像识别」的 `vlm` 任务，识别内容、人物、情绪、动作和图片文字，最多生成七个标签。未配置图像识别模型时保留待识别状态；配置后后台继续处理。失败任务不会反复自动请求，可点击「重试识别」。GIF 识别使用首帧缩图，预览和发送保留原始动画文件。

按描述找图使用 `planner` 任务从标签排序后的最多 16 个候选中选择，排除原表情包库已丢弃的图片；模型判断无匹配时不发图，模型请求失败时使用有实际命中的标签匹配，不随机发送。页面搜索按文件名和标签筛选。

## 自动收图

在表情包配置中开启「自动收图到额外图库」。默认关闭，不改变已有表情包收集设置。

| 配置项 | 行为 |
| --- | --- |
| `emoji.collect_images` | 收取入站私聊图片和表情包；每条消息最多处理 24 张，包括转发节点 |
| `emoji.image_collection_mode` | `whitelist` 只收名单内群聊，`blacklist` 收名单外群聊 |
| `emoji.image_collection_groups` | 群号列表；空白名单不收群图，空黑名单收所有群图；不影响私聊 |

单张图片最多 16 MB，图库最多 5000 张。达到容量后拒绝新增，不删除已有图片。原有 `emoji.steal_emoji` 继续控制原表情包库的自动注册，与额外图库收图分别设置。

## 数据与兼容

| 路径 | 内容 |
| --- | --- |
| `data/image_library/images/` | 图库原始文件，支持子目录 |
| `data/image_library/library.sqlite3` | 图片索引、手动标签、自动标签和识别状态 |
| `data/emoji/` | 「据为己用」产生的独立表情包副本 |

图库沿用 `smart_imagechat` 的 SQLite 数据格式和图片 ID，不改动原有表情包数据库结构。重复上传和扫描按图片内容去重，保留已编辑标签和识别结果；文件被替换后重新识别，文件被移除后扫描清理索引。无效文件保留在目录中，扫描结果显示错误。

从原插件迁移时，先停止 MaiBot 并卸载 `smart-imagechat.hub`，将其数据目录中的 `images/` 和 `library.sqlite3` 一起复制到空的 `data/image_library/`，再启动。不要用整库复制覆盖已有图库；已有图库可只导入图片后重新扫描。备份时停止程序并复制整个图库目录。删除图库图片不会删除已注册的表情包副本。

图库索引实现移植自本地 `smart_imagechat` 项目，其上游为青尘工作室的 [astrbot_plugin_smart_imagechat_hub](https://github.com/JREion/astrbot_plugin_smart_imagechat_hub)，遵循 GPL-3.0-or-later。消息收取、模型调用、发送、权限和界面使用 MaiBot 原生实现，无需额外服务或依赖。

## 限制

- 收图要求适配器提供图片字节；不下载缺少字节的远程图片。
- 图库搜索候选数量有限，标签不准确时可补充手动标签。
- 图片能否发送到外部平台仍由现有适配器能力决定。
