# 消息防抖

在 WebUI「麦麦设置 → 聊天 → 聊天设置」中，通过「群聊消息防抖（秒）」和「私聊消息防抖（秒）」滑动条分别设置等待时长。两项默认均为 **2 秒**，范围 **0–8 秒**，滑动步长 **0.1 秒**，也可直接输入数值。设为 **0** 关闭对应聊天类型的消息防抖。

```toml
[chat.reply_timing]
message_debounce_seconds = 2.0 # 群聊等待秒数，0 表示关闭
private_message_debounce_seconds = 2.0 # 私聊等待秒数，与群聊独立
```

## 等待规则

- 每个真实聊天流独立等待。第一条有效消息开启一批，等待设定的秒数；批次尚未到期时收到新消息，从这条消息起重新计算等待。
- 整批从第一条消息实际收到起最多等待 **8 秒**，连续消息不能重置这个上限。
- **@或提及最多等待 1 秒**；连续提及取最早的截止时间。这个上限与整批上限优先于自定义时长。
- 批次内的纯表情包不能延长等待，但可以让截止时间提前。纯表情包独立开启一批时，按设定的时长等待。
- 通知、命令和机器人自己的消息不更新防抖计时。

图片与表情包按原始组件和用户原文判断，不把识图描述当成用户文字。原始消息分别保留，等待结束后整批进入判断，保留发送者、引用和多媒体信息。

## 设置生效与消息接入

群聊、私聊设置独立支持热重载。修改时长从下一条有效消息起生效，不重置当前批次或提及上限，也不延长已到期批次；设为 0 会结束当前防抖等待。

防抖在消息进入 Planner 前、被新消息打断后重试前，以及后续轮次接入新消息前生效。新消息会唤醒异步等待，及时处理截止时间变化。

预处理耗时计入等待上限。媒体处理造成接收时间乱序时，不回退消息到达的时间轴，提及上限仍按实际收到时间计算。批次已到期而模型或工具仍在处理时，后来的消息留在原有缓存中一起消费，不再延长等待。

## 等待范围

防抖时长不包含模型生成和发送耗时。回复频率、Focus 准入与 Planner 的 wait 工具仍按各自规则运行；Focus 收到 @ 时沿用立即就绪策略。关闭防抖后仍可能存在这些机制产生的等待。
